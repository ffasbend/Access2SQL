## Session 1 — Bug fix: ORDER BY and DISTINCT not exported from Access queries

### Problem reported
The script did not correctly export `ORDER BY` clauses (and `SELECT DISTINCT`) from saved
queries in MS Access `.accdb` files.

### Investigation
Access stores saved query metadata in the system table `MSysQueries`. Each row has five
fields: `Attribute`, `Flag`, `Name1`, `Name2`, `Expression`.

The existing `_reconstruct_select_query_sql()` function already handled:

| Attribute | Meaning         |
|-----------|-----------------|
| 5         | FROM tables     |
| 6         | SELECT columns  |
| 8         | WHERE clause    |
| 9         | GROUP BY        |
| 10        | HAVING          |

By querying `MSysQueries` directly via `mdb-sql` on both test databases we discovered:

| Attribute | Flag | Meaning                     |
|-----------|------|-----------------------------|
| 11        | —    | ORDER BY expression         |
| 3         | 2    | SELECT DISTINCT modifier    |
| 3         | 1    | plain SELECT (no modifier)  |

Example raw rows for `Query1` (`SELECT DISTINCT … ORDER BY CodeExercice`):
```
6|0|||CodeExercice
5||Composer||
8||||NoWorkout IN (SELECT …)
11||||CodeExercice
3|2|||
```

Example raw rows for `Query5` (`SELECT … ORDER BY SUM(…)`):
```
6|0|||NoWorkout
6|0|Durée totale du workout||SUM(Durée * Répétition)
5||composer||
9|0|||NoWorkout
11||d||SUM(Durée * Répétition)
```

The `Name1='d'` field on attribute-11 rows appeared in one query but had no effect on the
expected ASC output — it is an internal Access reference that can be safely ignored.

### Root cause
Queries that had explicit SELECT columns (attribute-6 rows present) were returned by
`_reconstruct_select_query_sql()` without `ORDER BY` or `DISTINCT`, because those
attributes were never read. The `mdb-queries` fallback was only reached for `SELECT *`
queries (no attribute-6 rows), which is why those happened to work correctly.

### Fix applied (`access2sql.py`)
```python
# DISTINCT: attribute 3 with flag == "2"
is_distinct = any(r.get("flag") == "2" for r in rows if r["attribute"] == "3")

# ORDER BY: attribute 11
order_by_parts = [r["expression"].strip() for r in rows if r["attribute"] == "11" and r["expression"].strip()]

select_keyword = "SELECT DISTINCT" if is_distinct else "SELECT"
sql = select_keyword + " " + ", ".join(projections)
...
if order_by_parts:
    sql += " ORDER BY " + ", ".join(order_by_parts)
```

## Session 3 — GUI + standalone macOS app (v1.1)

### Goal
Wrap the CLI script in a drag-and-drop GUI that can also be packaged as a self-contained
`.app` on macOS (no Python or Homebrew required for end users).

### Framework choice
`tkinter` + `tkinterdnd2` — tkinter was already a dependency (used for the folder picker),
so `tkinterdnd2` is the only new package. Degrades gracefully: if `tkinterdnd2` is not
installed the GUI still works, just without drag-and-drop.

### New file: `access2sql_gui.py`
Key design decisions:

- **Separate file** — keeps the CLI script fully intact and importable; the GUI is a thin
  frontend that imports `VERSION`, `find_access_files`, and `export_db` from `access2sql`.
- **Background thread** — `export_db` is called in a `threading.Thread` so the GUI stays
  responsive during long exports.
- **Stdout redirect** — a `_QueueStream` object replaces `sys.stdout`/`sys.stderr` during
  export; the main thread polls the queue every 80 ms and appends lines to the dark log
  widget. This requires zero changes to `export_db` itself.
- **Duplicate prevention** — `_add_paths()` keeps a `set` of already-queued paths so
  dropping the same file twice is a no-op.
- **Two browse buttons** — "Browse files…" (multi-select file picker) and "Browse folder…"
  (recursive scan) rather than a confusing single button or dialog.

### macOS bundling: the mdbtools problem
On macOS the conversion backend is `mdbtools` — a set of native CLI tools installed via
Homebrew. PyInstaller can bundle Python code but not system binaries automatically.

**Solution:**
1. Copy the mdbtools executables from Homebrew into a staging directory.
2. Walk their dylib dependencies recursively using `otool -L`.
3. Rewrite all dylib references with `install_name_tool` to use `@loader_path`-relative
   paths so they resolve inside the bundle without Homebrew.
4. Pass everything to PyInstaller via `--add-binary`.

At runtime, `_mdb_binary(name)` checks `sys._MEIPASS` (PyInstaller's temp extraction
directory) for a bundled copy before falling back to PATH:

```python
def _mdb_binary(name: str) -> str:
    base = getattr(sys, "_MEIPASS", None)
    if base:
        candidate = Path(base) / "mdbtools" / "bin" / name
        if candidate.exists():
            return str(candidate)
    return name
```

All `subprocess` calls to mdbtools binaries route through `_mdb_binary()` — either
directly or via the updated `_run()` which checks `_MDB_TOOL_NAMES`.

### New file: `build_mac.py`
Single-command build:
```bash
python3 build_mac.py
# produces dist/Access2SQL.app
```

Prerequisites (developer machine only, not needed by end users):
```bash
brew install mdbtools
pip install pyinstaller tkinterdnd2
xcode-select --install   # for otool / install_name_tool
```

### Version bump
`VERSION` updated `"1.0"` → `"1.1"` for this feature release.
